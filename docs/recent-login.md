# 최근 로그인 수단 안내

로그인 화면에서 `GET /api/auth/recent-login`을 호출하면 **현재 브라우저에서 마지막으로 로그인에 성공한 수단**을 조회할 수 있습니다. 로그인이나 CSRF 토큰이 필요하지 않으며, 조회만으로 세션을 생성하지 않습니다.

```http
GET /api/auth/recent-login
```

```json
{
  "loginType": "KAKAO",
  "label": "카카오",
  "message": "이 브라우저에서 최근 카카오로 로그인했어요.",
  "available": true
}
```

| loginType | label | 로그인 방식 |
| --- | --- | --- |
| `NORMAL` | 이메일 | 이메일·비밀번호 |
| `KAKAO` | 카카오 | 카카오 소셜 로그인 |
| `NAVER` | 네이버 | 네이버 소셜 로그인 |
| `GOOGLE` | 구글 | 구글 소셜 로그인 |

기록이 없거나 쿠키가 만료·삭제되었거나 값이 유효하지 않으면 HTTP 200으로 다음을 반환합니다.

```json
{
  "loginType": null,
  "label": null,
  "message": null,
  "available": false
}
```

프런트는 `loginType`이 있을 때 `message`를 표시하고 해당 로그인 버튼에 ‘최근 사용’ 배지를 붙이면 됩니다. 이전에 사용한 소셜 제공자의 서버 설정이 해제된 경우에는 기록을 반환하되 `available: false`로 안내합니다. 이때 해당 소셜 로그인을 권유하지 않도록 처리합니다. 실제 사용 가능한 소셜 로그인 목록은 기존 `GET /api/auth/social/providers`로 조회합니다.

## 저장 시점

- 이메일·비밀번호 로그인 성공: `NORMAL`로 갱신합니다.
- 기존 회원의 소셜 로그인 성공: 해당 제공자로 갱신합니다.
- 소셜 가입 대기 후 추가 가입 또는 기존 계정 연결을 완료해 정식 회원으로 로그인한 경우: 해당 제공자로 갱신합니다.
- 로그인 실패, 동의 취소, 소셜 가입 대기, 가입·연결 실패: 기존 기록을 유지합니다.
- 이미 로그인한 회원이 소셜 계정만 연결한 경우: 기존 로그인 기록을 유지합니다.
- 로그아웃: 인증 세션만 종료하고 최근 로그인 안내는 유지합니다.

## 쿠키 및 연동

`BOGEUM_RECENT_LOGIN` 쿠키에는 위 `loginType` 값만 저장합니다. 회원 ID, 이메일, 비밀번호, 소셜 토큰은 저장하지 않습니다. 마지막 로그인 성공부터 30일 동안 유지하며 `HttpOnly`, `SameSite=Lax`, `Path={contextPath}/api`를 사용합니다. HTTPS 요청에서는 `Secure`도 설정합니다. TLS를 프록시에서 종료하는 배포 환경에서는 서버가 요청의 HTTPS 여부를 올바르게 인식하도록 설정해야 합니다.

프런트는 쿠키를 직접 읽지 않고 API로 안내 정보를 받습니다. 현재 Vite `/api` 프록시에서는 `fetch('/api/auth/recent-login')`으로 조회하면 됩니다. 기존 로그인 응답 본문과 소셜 OAuth 콜백의 JSON 응답 형식은 변경하지 않았습니다.

응답은 `Cache-Control: no-store`로 반환합니다. 이 정보는 브라우저별 편의 안내이며 서버의 계정별 로그인 이력이 아닙니다. 공용 브라우저에서는 다른 사용자의 최근 수단이 보일 수 있고 쿠키 값도 변조될 수 있으므로, 인증이나 계정 조회·접근 권한 판단에는 사용하지 않습니다.

`backend/requests/auth.http`에서 로그인 전 조회 → 로그인 → 조회 → 로그아웃 → 조회 흐름을 확인할 수 있습니다. HTTP 클라이언트의 쿠키 저장 기능을 켜야 합니다.
